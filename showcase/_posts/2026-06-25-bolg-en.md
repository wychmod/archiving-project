## Overview

`bolg` (self-described as "blog", with a suspected spelling slip in the name) is a **Flask full-stack blog
practice project** organized with the application factory pattern. It covers registration with email
activation, post publishing, a personal center, favorites, and search — the output of my early Flask learning phase.

**Status**: Archived — source kept for reference (feature completeness varies; the original README lists a
"to be finished" section).

## Tech Stack

| Layer | Choice |
| --- | --- |
| Backend | `Python 3` · `Flask` (application factory) |
| Sessions | `Flask-Login` |
| Data | `Flask-SQLAlchemy` · `Flask-Migrate` + `Alembic` · `SQLite` |
| Forms | `Flask-WTF` (WTForms) |
| Templates | `Jinja2` (folder-based) with a custom pagination macro |
| Engineering | Multi-environment config (`default / development / testing / production`) |

## Architecture Highlights

- **Application factory**: `create_app(config_name)` avoids circular imports; extensions are instantiated centrally in `extensions.py`
- **Layered codebase**: models, forms, and views each live in their own package, with templates grouped by domain
- **Email activation flow**: registration mail plus an activation link, with SMTP credentials read from environment variables (the right way)
- **Many-to-many relations**: posts ↔ users who favorited them — a hands-on ORM modeling sample
- **Reusable pagination macro**: `page_macro.html` wraps the pagination widget for every list page

## What It Taught Me

The project walks through Flask's core extensions (Login / SQLAlchemy / Migrate / WTF), but the more lasting
outcome is the habit of "application factory + multi-environment config + centralized extension setup" — a
structure that still holds up in larger projects.
