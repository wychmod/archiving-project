### 1.4 现有体验的问题(设计视角)

1. **定位错位** —— Chirpy 是博客优先(侧边栏 + 卡片流 + TOC),而本仓库的资产是「12 个项目 × 4 分类 × 2 语言」的
   **索引结构**。首页把 24 篇文章平铺成博客流,抹掉了「项目」这个第一公民。
2. **双语体验弱** —— 语言切换只是侧栏底部一行文字链接(`EN` / `中文`),无持久化、无视觉权重、
   详情页无「同级译文」感知,英文读者几乎发现不了。
3. **元数据不结构化** —— 技术栈、状态(已归档/已脱敏)、来源、commit 数都埋在正文散文里,
   无法筛选、无法聚合、无法在卡片上呈现。
4. **视觉无差异化** —— 1:1 复刻主题 Demo,「专业、精致、大气」无从体现;深色/浅色靠外部字体 CDN。
5. **缺图为常态** —— 12 个项目没有封面图,卡片只能靠纯文字,视觉密度低。
6. **导航层级扁平** —— 侧栏 5 项 + 分页流,没有「分类 → 项目 → 详情」的收敛路径。
7. **维护税高** —— 主题升级需要 diff 两处覆盖文件;Ruby 工具链重;`future: false` 等隐性规则容易踩。

### 1.5 重构不可破坏的资产

- ✅ 24 篇文章正文内容与 `ref` / `lang` 配对关系
- ✅ 4 个分类的语义(可换视觉,不换分组逻辑)
- ✅ 文章 URL 形态 `/posts/<slug>/`(或提供等价重定向)
- ✅ `/feed.xml` 与 sitemap 存在性
- ✅ GitHub Pages + Actions 的零成本、零服务器部署
- ✅ 仓库根文档(`README.md` / `AGENTS.md` / `CLAUDE.md`)中的引用口径

## 2. 设计目标与原则

### 2.1 定位转变

| | V1(现状) | V2(本方案) |
| --- | --- | --- |
| 心智模型 | 一个博客站 | 一座**归档年鉴 / 项目索引馆** |
| 首页 | 文章流 | **策展式首页**:主张 + 分类入口 + 精选项目 + 时间线叙事 |
| 第一公民 | 文章(post) | **项目(project)** |
| 双语 | 附属功能 | **一等公民**(路由级、导航级、内容级) |
| 视觉气质 | 通用博客主题 | 靛蓝 + 铜金的「档案馆」精致语言 |
| 技术 | Jekyll + gem 主题 | 自建静态站(见 §8) |

### 2.2 设计原则

1. **索引优先** —— 任何一屏都要能回答「这里有什么、怎么找」。分类 / 技术栈 / 时间线是三条检索主干。
2. **结构可见** —— 把 front matter 里的元数据(状态、技术栈、语言、来源)提升为**可见的结构化视觉元素**,
   而不是散文。
3. **克制的精致** —— 用一套严格的令牌(色彩 / 字阶 / 间距 / 圆角 / 阴影)约束所有页面,
   靠**层次与留白**而非装饰取胜。
4. **双语无感** —— 语言是路由维度,不是「隐藏的高级功能」;切换即换站,位置记忆、内容对齐。
5. **无图也体面** —— 封面由「分类色渐变 + 项目字标 + 几何纹理」程序化生成,视觉密度不依赖位图。
6. **可访问性即质量** —— 对比度、键盘可达、动效降级是交付门槛,不是附加项。

## 3. 信息架构(IA)

### 3.1 站点地图

```
/                         首页(策展式)
├── /projects/            项目库(全量 12,可筛选/切换视图)
│   └── /projects/<ref>/  项目详情(正文 + TOC + 译文切换 + 相关项目)
├── /timeline/            归档时间线(按归档日期叙事)
├── /stack/               技术栈总览(按后端语言 / 前端栈 / 架构风格分组)
├── /about/               关于(仓库自述 + 规范 + License)
├── /search/              搜索(⌘K 弹层优先,独立页兜底)
├── /404                  未找到
└── /en/…                 英文镜像路由(与中文一一对应)
```

> 与 V1 的对应:`/`(home layout)→ 策展式首页;`/archives/` → `/timeline/`;
> `/categories/*` + `/tags/*` → 合并收敛为 `/projects/`(筛选)+ `/stack/`(聚合);
> `/posts/<slug>/` → `/projects/<ref>/`(旧 URL 出重定向页)。

### 3.2 导航结构(三层)

| 层级 | 位置 | 组成 |
| --- | --- | --- |
| **全局导航** | 顶部固定栏(64px) | 字标 Logo · `首页` `项目库` `时间线` `技术栈` `关于` · 搜索 · 语言分段控件 · 主题切换 · GitHub |
| **局部导航** | 页面内 | 项目详情的双栏 TOC(桌面粘性 / 移动折叠);项目库的筛选栏(桌面 sticky) |
| **补充导航** | 页脚 + 页内 | 页脚四列站点地图;详情页「上一篇 / 下一篇」「同分类推荐」;全站回到顶部 |

**层级规则**:全局导航**只放 5 项**,不放分类;分类通过首页入口与项目库筛选承载,避免导航膨胀。

### 3.3 内容模型(设计侧字段规格)

每个「项目」在设计上被抽象为以下字段,全部来自现有 front matter + `ARCHIVE.md`,不新增事实:

| 字段 | 类型 | 视觉落点 |
| --- | --- | --- |
| `ref` | 字符串(=`archived-projects/` 目录名) | URL、译文配对键、封面种子 |
| `title` / `titleEn` | 字符串 | 卡片标题、详情 H1(中英并置) |
| `summary` | 字符串(≤90 字) | 卡片摘要(2 行截断)、详情导语 |
| `category` | 枚举(4 值) | 分类徽章 + 分类色 + 筛选维度 |
| `stack` | 字符串数组 | 技术栈 chips、`/stack/` 聚合、筛选维度 |
| `status` | 枚举:`archived` / `scrubbed` / `runnable` | 状态印章(铜金 / 中性 / 绿) |
| `archivedAt` | 日期 | 卡片元信息行、时间线节点 |
| `source` | URL | 详情「源码入口」卡 |
| `metrics` | 可选(commit 数等) | 详情元信息条 |
| `lang` | `zh-CN` / `en` | 路由前缀与界面语言 |

## 4. 页面结构与布局

### 4.1 全局骨架

```
┌──────────────────────────────────────────────────────────┐
│  Topnav 64px — 字标 · 主导航 · 搜索 · 语言 · 主题 · GitHub   │  sticky, 滚动后加毛玻璃+描边
├──────────────────────────────────────────────────────────┤
│                                                          │
│                    Main  <main>                          │
│      容器:content 1200 / wide 1360 / reading 720          │
│                                                          │
├──────────────────────────────────────────────────────────┤
│  Footer — 4 列站点地图 + 底栏(版权 · 构建信息 · License)     │
└──────────────────────────────────────────────────────────┘
      悬浮层:搜索弹层 / 移动端抽屉 / 回到顶部
```

- **容器**:`content` 最大 1200px(列表与栅格)、`wide` 1360px(首页 Hero 区)、`reading` 720px(正文)
- **栅格**:12 列,槽宽 24px(桌面)/ 16px(平板及以下)
- **垂直节奏**:区块间距 `clamp(64px, 8vw, 120px)`;区块内元素间距按 §6.3 令牌

### 4.2 首页(策展式,10 个区块)

| # | 区块 | 组成与层级 | 说明 |
| --- | --- | --- | --- |
| A | **Hero** | overline(ARCHIVE · 归档年鉴)→ H1 主标题 → 英文 tagline → 定位段(3 行)→ 双 CTA(浏览项目 / GitHub) → 右侧视觉(程序化网格 + 分类色光斑) | 左 7 : 右 5;H1 用 `display-1` |
| B | **数字带** | 4 个统计卡:12 个项目 · 9+ 技术栈 · 24 篇文档 · 2 种语言 | 一行 4 列,Hero 下沿重叠卡(负 margin 24) |
| C | **四条主线** | 4 张分类卡:分类色带 + 图标 + 分类名 + 项目数 + 代表项目名 ×3 | 点击进 `/projects/?category=` |
| D | **精选项目** | 3 张项目大卡(封面 + 分类徽章 + 标题 + 摘要 + 技术栈 chips + 状态印章) | 手选:TokenBridge / Lottery / ascvd |
| E | **项目总览** | 筛选 chips 行 + 12 项网格(3 列);右上「查看全部 →」 | 首页只展示首屏 6 项 + 查看全部 |
| F | **技术栈分布** | 左:后端语言条形图(占比 + 项目数);右:前端/架构标签云(词频定字号) | 数据来自 §3.3 的 `stack` 字段聚合 |
| G | **归档时间线** | 横向时间轴,12 个节点按年月排列,节点 = 日期 + 项目名 + 分类色点 | 横向可滚动,右侧「完整时间线 →」 |
| H | **方法论三段** | 三列:可检索 / 可对照 / 可托底(图标 + 短语 + 一句说明) | 引自根 README「它解决什么问题」 |
| I | **CTA 条** | 全宽浅色带:一句邀请 + 两个按钮(查看规范文档 / 归档工作流) | 铜金细边点缀 |
| J | **页脚** | 4 列:站点(5 导航)/ 项目(12 快捷)/ 规范(`AGENTS.md` `CLAUDE.md` `DESIGN`)/ 联系(GitHub · Email · RSS) | 底栏含构建时间与 License |

### 4.3 项目库 `/projects/`

```
面包屑 → 页头(标题 + 计数「12 个项目」+ 视图切换[网格|列表])
筛选栏(桌面 sticky,top=64)
  ├─ 分类 chips(4,单选)
  ├─ 技术栈多选(下拉多选 + 已选 chips 可移除)
  ├─ 状态(已归档 / 已脱敏)
  └─ 右侧:排序(归档时间 ↓ / 名称 ↑)+ 「清除筛选」
结果区
  ├─ 网格视图:3 列项目卡
  └─ 列表视图:紧凑行(封面色条 4px + 标题 + 摘要 + chips + 元信息)
空态(无匹配):图标 + 提示 + 「清除筛选」
```

- **卡片规格**:圆角 14,封面 2:1 程序化渐变,内容区 24px 内边距,`hover` 抬升 2px
- **列表视图**:行高 88px,左色条标识分类,移动端自动降级为网格
- **筛选即 URL**:筛选状态写入 query(`?category=&stack=&status=`),可分享、可回退

### 4.4 项目详情 `/projects/<ref>/`

| 区块 | 组成 |
| --- | --- |
| 面包屑 | `首页 / 项目库 / <分类> / <项目名>` |
| **头图区** | 分类色渐变大卡(高 240–320):项目名(中文,H1)+ 英文名(次级)+ 一句话摘要 + 状态印章 + 技术栈 chips + 元信息条(归档日期 · commit 数 · 语言) |
| 动作区 | 主按钮「查看源码」· 次按钮「GitHub」· **语言分段控件(中 / EN)** · 分享 |
| 正文(左,720) | `概览` → `技术栈`(表格) → `架构亮点` → `学习收获` → `归档信息`(来源卡) |
| TOC(右,240) | 粘性 `top:96px`,H2 锚点列表,当前项高亮 + 左侧 2px 品牌色指示条 |
| 底部关联 | 上一篇 / 下一篇(双卡)+「同分类项目」3 卡 |
| 阅读进度 | 页面顶部 2px 品牌色进度条(`scroll` 驱动) |

**相对 V1 的三处设计升级**:
1. 技术栈从散文/表格升级为**表格 + chips 双表现**;
2. 状态从正文括号升级为**印章式徽章**,置顶可见;
3. 语言从侧栏文字链升级为**头图区分段控件**,位置显眼。

### 4.5 时间线 `/timeline/`

- 顶部统计带:项目总数 · 跨度(2026-06 → 2026-09)· 最后归档时间
- 主区:**左轴竖直时间线**,按「年 → 月」分组,组标题为 sticky 小标题
- 节点组成:节点圆点(分类色,当前项放大)→ 日期(`2026-09-22`)→ 项目名(链接)→ 一句话 → 状态印章
- 节点间连接线 1px `line-soft`;hover 时节点圆点外扩 2px 光环
- 移动端:整体左移,轴距左侧 20px,节点卡片占满剩余宽度

### 4.6 技术栈 `/stack/`

- 三分组:**后端语言** / **前端栈** / **架构风格**
- 每项为一行:图标(品牌色) + 名称 + 进度条(按项目数占比,5 个计数上限归一) + `n` + 代表项目链接
- 顶部锚点跳转条(三组)
- 尾部「全部标签」云区:按词频字号 13→22px 阶梯,芯片样式,点击进 `/projects/?stack=`

### 4.7 关于 `/about/`

- 引语开场(衬线字体,1 句仓库主张)
- 三问卡:**它是什么 · 为什么保留 · 现在还活着吗**
- 两组对照表:「它解决什么问题」(4 条,图标列)/「它不是什么」(3 条,禁用样式)
- 归档构成表(4 分类 × 项目)
- 资源卡区:仓库 / `AGENTS.md` / `CLAUDE.md` / 站点设计文档 / License
- 维护者卡:头像 + 链接

### 4.8 404

- 大号 `404` + 一句话 + 「返回首页 / 浏览项目库 / 搜索」三入口 + 4 个分类快捷卡

## 5. 交互规范

| 交互 | 规格 |
| --- | --- |
| **导航当前项** | 半透明品牌底 + 底部 2px 品牌色指示条;切换页面时指示条 220ms 平移 |
| **下拉/抽屉** | 移动端汉堡 → 全屏抽屉(白底,列表字号 20px,分组:主导航 / 语言 / 主题 / 社交);打开锁滚动 + `Esc` 关闭 + focus 陷阱 |
| **语言切换** | 分段控件 `中 \| EN`;切换等价页(同 `ref` 译文),无译文则回退该语言首页;偏好写 `localStorage` 并同步 `<html lang>`;详情页切换后**保持滚动位置比例**并短暂高亮标题 |
| **主题切换** | 三态:跟随系统 / 浅 / 深;首屏内联脚本写 `data-theme`,**杜绝闪白**;与系统主题变化实时联动 |

### 7.3 专项适配

- **触摸目标**:所有可点击元素最小 44 × 44px 命中区(chips 视觉 26px,但 padding 撑到 44)
- **表格**:`<768` 一律转卡片堆叠(标签 + 值),横向滚动仅作兜底
- **图片**:封面为 CSS 生成(零请求);真实截图 `srcset` + AVIF/WebP + `aspect-ratio` 占位;
  2x 屏提供 2x 资源上限 2400px
- **容器查询**:项目卡、筛选 chip、技术栈行使用 `@container`,同一组件在侧栏与主区自适应,
  减少「为位置写断点」
- **超大屏(≥1536)**:内容不再拉宽,而是增加左右留白;首页区块可切「双列并置」以利用横向空间
- **安全区**:移动端底部吸附元素加 `env(safe-area-inset-bottom)`
- **打印**:详情页打印样式隐藏导航 / TOC / 页脚,正文黑色 100% 宽度

### 7.4 无障碍(与响应式同权重)

- WCAG 2.1 **AA**:正文对比 ≥ 4.5:1,大字 ≥ 3:1,非文字(边框、图表)≥ 3:1
- 全键盘可达 + 可见焦点;弹层 / 抽屉有 focus 陷阱与 `Esc` 关闭

## 11. 落地状态与偏差记录

**状态:已实施。** 按 §10 的 P0–P7 全阶段落地,`npm run build` 产出 **35 页**(中 18 + 英 17,含 404),页面已逐张核对;交互(Ctrl+K 搜索、分类筛选、网格/列表切换、语言切换、主题切换、回到顶部)已实测通过。

与本文设计的偏差,及原因:

| 项 | 设计(§) | 实际落地 | 原因 |
| --- | --- | --- | --- |
| 搜索 | Pagefind WASM(§8.1 C10) | **构建期生成 `search-index.json` + 客户端打分** | 索引体量极小(24 条),无需引入 WASM 运行时与额外构建步骤;搜索结果可完全控分(名称 > 栈 > 分类 > 摘要) |
| 包管理 | pnpm(§8.4) | **npm**(提交 `package-lock.json`) | 不引入额外前置依赖;CI 用 `actions/setup-node` 的 npm 缓存即可 |
| Node | 20(§8.4) | **22** | 与仓库其他项目对齐 |
| 死链校验 | `lychee` 外链抽查(§8.1 C12) | **自建 `scripts/check-links.mjs`**(校验所有内链都在部署 base 内) | 本项目真正的失败模式不是外链失效,而是「某个内链漏了 base 前缀」——只在部署后才暴露。该脚本直接扫 `dist/` 全部 HTML,CI 门禁 |
| 令牌校验 | 未预见 | **新增 `scripts/check-tokens.mjs`** | 实施中发现 `var(--x)` 引用不存在的令牌会静默丢弃整条声明,不报错。该脚本比对全量引用与定义 |

实施中暴露的 4 个非显而易见陷阱(已在代码内就地注释,避免后人重踩):

1. **`hidden` 属性会被组件样式击败** — `.search{display:flex}` 特异性高于 UA 的 `[hidden]`,搜索弹层默认常驻可见。全局加 `[hidden]{display:none!important}`。
2. **Astro 作用域样式够不到子组件元素** — 筛选用的 `[data-hidden='true']` 编译后带本 layout 的 `data-astro-cid`,而卡片由另一个组件渲染,导致筛选只改 URL 与计数、卡片不隐藏。该规则必须放在全局层。
3. **Astro 不给 redirect 目标补 base** — 旧 URL 重定向会跳出部署子路径。需在 `astro.config.mjs` 统一补前缀。
4. **Windows/Git Bash 会改写 `PAGES_BASE_PATH`** — `/archiving-project` 被翻译成 `C:/…/archiving-project`,静默产出全站错链。配置内加了「非 POSIX 绝对路径即报错」的守卫,本地构建需 `MSYS_NO_PATHCONV=1`。

> §9 的性能门禁(首屏 JS ≤ 60KB gzip、Lighthouse ≥ 95 等)尚未在 CI 中做阈值断言,属已知待办。
